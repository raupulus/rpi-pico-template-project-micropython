# Módulo: `Drivers/CC1101.py`

Driver de bajo nivel para la comunicación SPI con el transceptor de radiofrecuencia Texas Instruments CC1101.

## Qué hace y qué NO hace

### Qué hace
- Configura el transceptor CC1101 mediante SPI (Modo 0, polaridad 0, fase 0) a 4 MHz para operar en la banda europea ISM de **868.3 MHz**.
- Aplica modulación 2-FSK con tasa de símbolo de ~8.2 kbps y desviación de frecuencia de ~57.1 kHz.
- Gestiona los registros de demodulación, control de paquetes (`PKTCTRL0=0x02` para longitud variable) y filtro de ancho de banda (`MDMCFG4`).
- Ofrece strobes de control: reset (`SRES`), entrada en recepción (`SRX`), idle (`SIDLE`), flush de buffers FIFO (`SFRX`, `SFTX`) y calibración (`SCAL`).
- Recupera el receptor ante eventos de desbordamiento de FIFO (`MARCSTATE = 0x11`).
- Permite la lectura continua de paquetes con timeout o modo no bloqueante (`timeout_ms=0`).
- Convierte los valores crudos del registro RSSI a potencia recibida en dBm.
- Obtiene un diagnóstico completo del transceptor (`get_status()`).

### Qué NO hace
- No implementa transmisión de datos (TX). El proyecto opera exclusivamente en recepción pasiva (RX).
- No interpreta ni valida el contenido del payload decodificado (responsabilidad de `WeatherSensor.py`).
- No maneja la interrupción física ni el bucle de procesamiento temporal.

## Flujos principales

### 1. Inicialización y Configuración Bresser
```
reset() -> Strobe SRES
  │
  ▼
configure_bresser(pkt_len=40, strict_sync=False, bw_profile='270k', freq_hz=868300000)
  │
  ├─► Strobe SIDLE
  ├─► Flush FIFOs (SFRX, SFTX)
  ├─► Escritura de registros base (IOCFG, PKTCTRL, FREQ, MDMCFG, DEVIATN, MCSM)
  ├─► Strobe SCAL (calibración del sintetizador)
  └─► enter_rx() -> Strobe SRX
```

### 2. Ciclo de Lectura de Paquete (`read_packet`)
```
read_packet(timeout_ms)
  │
  ├─► ensure_rx() (comprueba MARCSTATE y limpia overflow si existe)
  ├─► Consulta rx_bytes_available()
  ├─► Lee byte de longitud L desde FIFO (si L == 0 o L > PKTLEN -> recupera overflow y descarta)
  ├─► Espera y lee los L bytes restantes
  └─► Devuelve bytes([L] + payload)
```

## Puntos de entrada

- `CC1101(spi, cs, gdo0=None, gdo2=None, debug=False)`: Constructor con bus SPI y pin de Chip Select.
- `reset() -> None`: Reinicio hardware por CS y strobe por software.
- `configure_bresser(pkt_len=27, strict_sync=False, bw_profile='270k', freq_hz=None) -> None`: Carga completa del perfil de registros Bresser.
- `set_bw_profile(bw_profile='270k') -> bool`: Modificación dinámica del ancho de banda (`270k`, `250k`, `100k`).
- `enter_rx() -> None`: Transición limpia a modo de recepción.
- `ensure_rx() -> None`: Comprobación del estado MARCSTATE y auto-recuperación de desbordamientos.
- `read_packet(timeout_ms=100) -> Optional[bytes]`: Extracción de un paquete completo del FIFO.
- `rx_bytes_available() -> int`: Número de bytes pendientes de lectura en el FIFO de recepción.
- `get_rssi_dbm() -> float`: Cálculo de la señal recibida en dBm.
- `get_status() -> dict`: Diagnóstico de telemetría interna del transceptor.

## Trampas conocidas

- **Pull-up en CS obligatorio**: El pin CS del CC1101 debe contar con una resistencia física de pull-up (10 kΩ a 3.3V). Durante el reset o flasheo del RP2040 los pines quedan en alta impedancia; sin pull-up, el CC1101 interpreta niveles bajos aleatorios como transacciones SPI no válidas.
- **Overflow de RX FIFO (MARCSTATE 0x11)**: El FIFO del CC1101 tiene 64 bytes. Si se acumulan ráfagas sin vaciar inmediatamente, el radio entra en bloqueo por overflow y no recibe más tramas hasta ejecutar un strobe `SIDLE` seguido de `SFRX`. El método `ensure_rx()` implementa esta protección.
- **Byte de longitud en variable length**: En modo `PKTCTRL0=0x02`, el primer byte en el FIFO es la longitud comunicada por el emisor. Si el ruido ambiental genera un falso sync word y un valor de longitud erróneo, se debe limitar la lectura a `PKTLEN` para no provocar bloqueos.
